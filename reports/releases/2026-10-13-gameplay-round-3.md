Memory storage rejects that write; Redis checks the existing completed-match set and writes the original JSON in one Lua operation. The API returns an owner-bound `MATCH_ALREADY_COMPLETED` conflict. Only that old table pauses its saves and displays `Match finished · saves paused`; the signed-in account, current checkpoint and ability to keep playing remain available. Save & exit stays at the table after refusal. Unconfirmed Redis replies remain retryable service failures.
- A fresh authenticated browser automatically posted its empty local favorites, erasing the cloud collection. Session reads and sign-in now restore cloud favorites without posting. An already-open deck explorer also refreshes its favorite state after hydration, preserving its search, filters and selection so the next star click retains the restored collection. Explicit star edits serialize in click order; a concurrent same-owner refresh preserves pending stars while accepting newer match statistics. Account changes still restore the new account's preferences.
